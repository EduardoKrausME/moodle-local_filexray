Moodle file areas

Comparison includes logical file areas that may legitimately exist outside course contexts.

Components and file areas

The component value identifies the plugin or Moodle subsystem that manages a file, while filearea identifies the purpose of that content within the component. Each component can have different file ownership semantics.

user / draft

Draft and temporary uploads from editors and forms. These records are not automatically safe to delete, because an editing workflow may still be active.

user / backup

User backup files stored by Moodle. They may be required for export, recovery or download workflows.

user / icon and user / profile

Profile icon and other user-profile areas, depending on Moodle version and installed components. They may not appear in course backup inventories.

badges / badgeimage

Badge images used for achievement credentials and their presentation.

backup / *

Component-wide total across file areas owned by backup. Such totals are not additive with a breakdown of the same component's file areas.

core_h5p / *

Totals across H5P-related file areas. These files may be legitimate independently of a course backup inventory.

Interpreting totals

Summed filesize values represent logical bytes. Component-wide totals can overlap with rows for their individual file areas. The comparison separately reports records outside the current report's backup inventory.

User files, backup files, badges and H5P content should be investigated individually, even when no course backup references were found.
