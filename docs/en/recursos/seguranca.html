Security, limitations and privacy

File X-Ray is a diagnostic tool, not a substitute for institutional retention rules or independent storage verification.

Moodle capabilities

Reading inventory reports requires local/filexray:view. Creating, resuming and deleting reports requires local/filexray:run. Checks run in Moodle's system context.

No deletion of Moodle files

Deleting a report removes only File X-Ray's own report, course and inventory records. It does not delete mdl_files records or original physical files. There is no built-in action to purge presumed orphans.

Stored data

Reports include the creator's Moodle user ID and metadata such as course and file IDs, names, components, file areas, contexts, hashes, sizes, timestamps and errors. Treat these records as internal institutional information.

File preview

Images, PDFs and supported media are previewed within the Moodle installation. Office documents require an administrator to explicitly approve transfer to Google Docs Viewer. A signed link valid for up to ten minutes enables Google to fetch the file. Do not use this external service for confidential documents without institutional approval; authenticated download remains available, including when the site is not publicly reachable over HTTPS.

Retention

Administrators may set the maximum number of saved reports. When the limit is reached, creating a new report removes the oldest report first.

Technical scope

File X-Ray cannot verify every third-party component's references, does not scan physical moodledata/filedir for orphan hashes and does not prove a file is safe to remove. Changes during processing can affect comparison totals.

Handling failures

A failed course makes a comparison provisional, and administrators can retry the failed jobs. Verify results in a staging environment before carrying out any independent storage cleanup.

Always use tested backups and institution-approved retention policies before deciding to remove Moodle data outside File X-Ray.
