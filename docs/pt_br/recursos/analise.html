Como funciona o inventário

O File X-Ray reutiliza o plano nativo de backup para descobrir referências sem copiar arquivos para um novo pacote.

Um curso por execução

O relatório guarda uma linha para cada curso. O executor adquire um bloqueio exclusivo do relatório, seleciona o próximo curso pendente e aciona o plano de backup do Moodle para esse curso. Não é um backup em lote e não depende de uma chamada AJAX demorada.

Referências nativas do backup

A execução percorre as tarefas de estrutura e anotação do backup, incluindo as contribuições dos componentes compatíveis. Depois que o Moodle consolida os IDs de arquivo, o File X-Ray grava registros selecionados a partir de backup_ids_temp e mdl_files, com identificador, hash, componente, área, contexto, nome e tamanho.

O ponto de parada

O processamento para antes de fileslist, a etapa que copiaria os conteúdos físicos e prepararia a relação final de arquivos. Também não executa a compactação ou o armazenamento de um MBZ. Arquivos XML e dados temporários podem ser gerados pelas etapas anteriores e são limpos depois.

O que entra no inventário

Entram as referências resolvidas pelos mecanismos de backup dos cursos e plugins compatíveis. O inventário não garante cobrir todas as áreas do Moodle, como arquivos de usuários, contextos globais ou componentes que não participem corretamente do backup de cursos.

Falhas e compatibilidade

Se uma tarefa de curso falha, o erro fica registrado na linha correspondente. A ordem das etapas de backup é relevante para o processo e deve ser verificada quando o Moodle for atualizado, especialmente em mudanças de API do subsistema de backup.

Uma referência não inventariada não equivale a um arquivo sem uso. A ferramenta mede o que o backup de cursos consegue encontrar, e não todas as relações possíveis do Moodle.
